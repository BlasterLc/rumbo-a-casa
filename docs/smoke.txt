# Contrato de API: `POST /api/chat`

Para conectar el chat y las tarjetas de resultado en la SPA. Complementa `docs/stack-tecnico.md`.

## Endpoint

```
POST https://d26duk07atmc3z.cloudfront.net/api/chat
Content-Type: application/json
```

## Request

```json
{
  "sessionId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "mensaje": "Hola, somos una familia de 3 en Valparaíso y queremos arrendar"
}
```

- `sessionId`: **UUID v4** generado por la SPA en el primer mensaje y guardado en `localStorage` (así la conversación persiste si la familia recarga la página). No lo genera el backend.
- `mensaje`: texto de 1 a 2000 caracteres. Se recorta espacios en blanco antes de validar.

## Respuestas

| Código | Cuerpo | Cuándo | Qué debería hacer la SPA |
|---|---|---|---|
| `200` | `{ respuesta, perfil, resultados, plan }` | OK | Mostrar `respuesta` en el chat y las tarjetas con `resultados`/`plan` |
| `400` | `{ error: "solicitud_invalida" }` | `sessionId` no es UUID, `mensaje` vacío/>2000 caracteres, o el cuerpo llega roto | Error de cliente — no debería pasar si la SPA arma bien la petición |
| `405` | `{ error: "metodo_no_permitido" }` | Se llamó con otro método que no es POST | No debería pasar en uso normal |
| `429` | `{ error: "limite_mensajes", mensaje: string }` | La sesión llegó a 40 mensajes | Mostrar el `mensaje` y ofrecer empezar una conversación nueva (nuevo `sessionId`) |
| `503` | `{ error: "asistente_no_disponible", mensaje: string }` | Bedrock falló o está saturado (throttling, timeout, cuenta en verificación) | Mostrar el `mensaje` y **ofrecer el modo demo** |
| `500` | `{ error: "error_interno" }` | Falla inesperada (ej. DynamoDB caído) | Error genérico, reintentar más tarde |

## Forma de los datos del `200`

### `perfil` — el perfil familiar tal como quedó después de este mensaje

13 campos, cada uno puede valer `"desconocido"` si todavía no se sabe:

```ts
{
  postulanteEdad: number | "desconocido",
  region: "Arica y Parinacota" | "Tarapacá" | "Antofagasta" | "Atacama" | "Coquimbo" |
          "Valparaíso" | "Metropolitana" | "O'Higgins" | "Maule" | "Ñuble" | "Biobío" |
          "La Araucanía" | "Los Ríos" | "Los Lagos" | "Aysén" | "Magallanes" | "desconocido",
  zonaEspecial: "chiloe" | "palena" | "isla_de_pascua" | "juan_fernandez" | "ninguna" | "desconocido",
  tramoRSH: number | "desconocido",              // 0-100
  tienePropiedad: boolean | "desconocido",
  ahorroUF: number | "desconocido",
  antiguedadCuentaAhorroMeses: number | "desconocido",
  ingresoFamiliarMensualUF: number | "desconocido",
  ingresoFamiliarMensualCLP: number | "desconocido",
  integrantesGrupoFamiliar: Array<{ edad: number, discapacidadCertificada: boolean }> | "desconocido",
  excepcionPostulacionIndividualDS49: boolean | "desconocido",
  subsidioPrevio: "DS49" | "DS1_T1" | "damnificado_2014" | "ninguno" | "desconocido",
  objetivo: "comprar" | "construir" | "arrendar" | "desconocido",
}
```

### `resultados` — SIEMPRE los 4 programas, en este orden: DS49, DS1, DS19, DS52

```ts
Array<{
  programa: "DS49" | "DS1" | "DS19" | "DS52",
  estado: "elegible" | "no_elegible" | "falta_dato",
  motivo: string,                    // explicación en lenguaje natural
  camposFaltantes?: string[],        // solo si estado === "falta_dato"
  regla: { decreto: string, fuente: string, fechaConsulta: string },
  detalle?: Record<string, unknown>, // ver nota importante abajo
}>
```

**⚠️ Importante para la UI — la nota de DS52 fuera de la Región Metropolitana:** cuando `region` no es `"Metropolitana"` (incluye `"desconocido"`), el resultado de DS52 trae `detalle.nota` con una advertencia tipo *"los montos son de RM, pueden variar según tu región/comuna, verifica en minvu.gob.cl"*. **Esta nota vive en `resultados[].detalle.nota`, no en `plan`** — hay que leerla desde `resultados`, no asumir que solo mostrando `plan` alcanza. Si la tarjeta de DS52 no muestra esto, una familia fuera de Santiago puede llevarse una cifra equivocada.

### `plan` — solo los programas con `estado === "elegible"`, en el mismo orden que `resultados`

```ts
Array<{
  programa: "DS49" | "DS1" | "DS19" | "DS52",
  documentos: Array<{ nombre: string, detalle?: string }>,
  fuente: string,   // de dónde sale esa lista de papeles
}>
```

Si ningún programa sale elegible, `plan` es `[]` (no falta el campo, es un arreglo vacío).

## Notas generales

- No hace falta login, CAPTCHA ni pedir Clave Única, RUT o datos bancarios — el asistente nunca los pide.
- El asistente responde en el idioma en que se le escribe (español o inglés).
- Cada respuesta `200` recalcula `resultados`/`plan` con el perfil actualizado — no hace falta pedirlos aparte, siempre vienen juntos con `respuesta`.
